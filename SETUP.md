# Налаштування збереження уроків у GitHub (безкоштовно)

Сайт може зберігати ваші власні уроки («Мої уроки») назавжди — прямо у файл `site/data/sets.json` у вашому репозиторії GitHub. Після кожного збереження Vercel автоматично оновлює сайт (≈ 1 хвилина), і урок з’являється на всіх пристроях.

Усе безкоштовно: GitHub (безкоштовний акаунт) + Vercel Hobby. Жодних платних сервісів і банківських карток.

Поки це не налаштовано, уроки все одно зберігаються у вашому браузері — просто не забувайте робити **Export backup** на головній сторінці.

---

## Крок 1. Створіть GitHub-токен (fine-grained) лише для репозиторію learnjapanese

1. Увійдіть на <https://github.com> під своїм акаунтом (**dzemod**).
2. Відкрийте: аватар (праворуч угорі) → **Settings** → внизу ліворуч **Developer settings** → **Personal access tokens** → **Fine-grained tokens**.
   Пряме посилання: <https://github.com/settings/personal-access-tokens/new>
3. Натисніть **Generate new token** і заповніть:
   - **Token name**: `kotoba-save` (будь-яка назва).
   - **Expiration**: виберіть строк (наприклад, 1 рік або «No expiration»). Коли токен закінчиться, просто створіть новий і замініть його у Vercel (крок 2).
   - **Resource owner**: ваш акаунт `dzemod`.
   - **Repository access**: **Only select repositories** → виберіть **dzemod/learnjapanese**.
4. У розділі **Permissions** → **Repository permissions** знайдіть **Contents** і виберіть **Read and write**.
   (Поруч автоматично з’явиться **Metadata: Read-only** — це нормально.) Більше нічого не вмикайте.
5. Натисніть **Generate token** і **скопіюйте токен** (починається з `github_pat_…`). GitHub покаже його лише один раз.

> Токен — це як пароль. Не надсилайте його нікому і не вставляйте в код. Він зберігається тільки у Vercel.

## Крок 2. Додайте змінні середовища у Vercel

1. Відкрийте <https://vercel.com> → ваш проєкт (learnjapanese).
2. **Settings** → **Environment Variables**.
3. Додайте першу змінну:
   - **Key**: `GITHUB_TOKEN`
   - **Value**: токен із кроку 1 (`github_pat_…`)
   - **Environments**: позначте **Production** (і за бажанням Preview).
   - Натисніть **Save**.
4. Додайте другу змінну:
   - **Key**: `APP_PASSWORD`
   - **Value**: придумайте свій пароль (наприклад, довга фраза). Його сайт попросить один раз на кожному пристрої.
   - **Environments**: **Production** → **Save**.

## Крок 3. Передеплойте сайт

Змінні середовища застосовуються лише до нового деплою:

1. У Vercel відкрийте вкладку **Deployments**.
2. Біля останнього деплою натисніть **⋯** → **Redeploy** → **Redeploy**.
3. Зачекайте ≈ 1 хвилину, поки статус стане **Ready**.

## Крок 4. Перевірка

1. Відкрийте сайт → **Створити мій урок**.
2. Вставте, наприклад, `見ます - дивитися` → **Розпізнати текст** → **Зберегти урок**.
3. Сайт попросить пароль (`APP_PASSWORD`) — введіть його. Він запам’ятається на цьому пристрої.
4. Має з’явитися «Збережено в GitHub ✓». У репозиторії на GitHub з’явиться новий коміт «Add my lesson …», а через ≈ 1 хв урок буде видно на всіх пристроях.

Перевірити, чи налаштування підхопилися, можна за адресою `https://<ваш-сайт>.vercel.app/api/save-set` — там має бути `{"configured":true}`.

## Якщо щось не працює

| Повідомлення | Що зробити |
|---|---|
| «Збереження в GitHub ще не налаштоване» | Немає `GITHUB_TOKEN` або `APP_PASSWORD` у Vercel, або ви не зробили Redeploy (крок 3). |
| «Неправильний пароль» | Введіть той самий пароль, що в `APP_PASSWORD`. Сайт спитає його знову при наступному збереженні. |
| «GitHub-токен недійсний або прострочений» | Створіть новий токен (крок 1), замініть `GITHUB_TOKEN` у Vercel, Redeploy. |
| «Токен не має дозволу на запис» | У налаштуваннях токена має бути **Contents: Read and write** і доступ до репозиторію `learnjapanese`. |
| «Функція збереження недоступна» | Ви відкрили сайт локально (`npx serve site`) — там API не працює. На Vercel усе працює. |

Уроки, які не вдалося зберегти, залишаються у браузері з позначкою «Лише тут» — натисніть **Зберегти в GitHub** пізніше або зробіть **Export backup**.

---

## Кандзі

Виправлення в розділі «Кандзі» (значення, читання, слова-приклади) зберігаються так само — через той самий `GITHUB_TOKEN` і `APP_PASSWORD`, у файл `site/data/kanji.json`. Нічого додатково налаштовувати не потрібно.
